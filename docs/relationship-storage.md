# Основная паутина и копии комнат

Применить `supabase/migrations/20261026180000_relationship_snapshots.sql` в SQL Editor проекта Supabase после предыдущих миграций комнат. Файл выполняется одной транзакцией. До применения серверное сохранение отключено; приложение показывает доступную паутину для чтения.

- `relationship_templates`: основная паутина Сказителя, владелец — его защищённая сессия комнат. Начальные данные включают книжный реестр и прежние локальные связи.
- `room_relationships`: независимая копия, привязанная к `rooms.id`. Кнопка добавления выполняет копирование один раз. Повторное добавление не заменяет существующую кампанию.
- Связи и полный список карточек НИПов находятся в одном снимке, включая НИПов без оставшихся связей.
- Изменение основной паутины не обновляет комнаты. Изменения комнаты не обновляют основную или другие комнаты.
- Сброс боя, закрытие вкладки и выход участника не удаляют снимок. Только удаление самой комнаты удаляет её копию через внешний ключ `ON DELETE CASCADE`.
- Новая таблица читается только участниками комнаты и изменяется только её Сказителем. Основной шаблон доступен только владельцу.
- Миграция переносит старые связи из `room_combat.state.relationshipWeb` вместе с встроенными карточками НИПов и добавляет книжную основу.

## JSON комнаты

Кнопка «Выгрузить комнату JSON» доступна Сказителю на странице комнаты и в пульте. Архив содержит метаданные комнаты, снимки участников, все сохраняющиеся в базе броски и запросы, бой и независимую паутину с НИПами. Ключ приглашения и идентификаторы аутентификации не выгружаются. Выгрузка не удаляет комнату и не заменяет её состояние.

Проверка после применения: открыть пульт, создать связь в основной паутине, добавить копию в комнату, изменить связь в комнате, переключиться на основную и убедиться, что она не изменилась. Выгрузить JSON и проверить `relationships.links` и `relationships.npcs`.
