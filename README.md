# Парма

Веб-приложение для игроков и мастера настольной ролевой игры «Парма»: электронные листы персонажей, игровые расчёты, справочники и боевой трекер в одном интерфейсе.

Приложение работает на стороне браузера. Учётные записи, серверная база данных и подключение к внешнему игровому серверу не требуются. Персонажи сохраняются локально; режим мастера обменивается состоянием с листами игроков в других вкладках **того же браузера и того же сайта**.

## Возможности

### Для игрока

- Создание героя: имя, раса и её вариант, бонус характеристики, предыстория, распределение до 10 очков навыков (не более 2 в один навык), стартовое снаряжение.
- Список персонажей с поиском по имени и расе, переходом к листу и подтверждением удаления.
- Характеристики, модификаторы и проверки навыков с бросками к100.
- Пять ресурсов: живучесть, жива, бодрость, влияние и благодать; расход, восстановление, короткий и продолжительный отдых.
- Бой: экипировка, броня, инициатива («прыть»), атаки, урон и взаимодействие с боевым трекером.
- Состояния и их длительность, спасброски, периодический урон, механики «Грани».
- Заклинания по школам, доступность по навыку, стоимость и результаты применения.
- Инвентарь, количество и использование предметов, вес, покупки и пересчёт валют.
- Личность: характер, идеал, привязанность, слабость, вдохновение, внешность, цели и история.
- Повышение уровня с выбором характеристики и бросками роста ресурсов; справочник доступных и будущих умений.

Лист персонажа содержит закреплённые переходы по разделам. Значения ресурсов дополнены шкалами; формы и основные элементы управления адаптированы для небольших экранов.

### Для мастера

- Общий обзор персонажей, брони, ресурсов и личности.
- Групповые запросы прыти, скрытности, наблюдательности и выживания, сбор результатов и броски за игроков.
- Боевой трекер: добавление игроков и противников, порядок инициативы, раунды, переход хода, здоровье участников и атаки противников.
- Бестиарий с масштабированием противников под выбранный уровень и копированием характеристик.
- Шпаргалка с игровыми правилами.

## Быстрый запуск

Нужны **Node.js 24+**, npm и современный браузер с поддержкой IndexedDB, BroadcastChannel и диалогов HTML. Версия Node.js для nvm указана в `.nvmrc`.

```bash
# Если используете nvm
nvm install
nvm use

# Установка зафиксированных зависимостей
npm ci

# Сервер разработки
npm run dev
```

Откройте адрес, выведенный Vite в терминале (обычно `http://localhost:5173`). Чтобы открыть браузер автоматически:

```bash
npm run dev -- --open
```

Переменные окружения и API-ключи для текущей версии не нужны. Если npm сообщает `EBADENGINE`, проверьте `node --version`: используйте версию из `.nvmrc`.

## Как пользоваться

### Создать персонажа

1. На главной нажмите **«Создать персонажа»**.
2. Введите имя, выберите расу, доступный вариант и предысторию.
3. Распределите очки навыков кнопками «+» и «−». Счётчик и шкала показывают оставшиеся очки.
4. Нажмите **«Сохранить персонажа»** — откроется лист героя.
5. Используйте меню разделов для перехода к ресурсам, бою, навыкам, магии, инвентарю и личности.

Изменения большинства игровых параметров сохраняются при действии. Текстовые поля биографии сохраняются после выхода из поля. Для повышения уровня используйте кнопку **«+1 уровень»** в шапке листа.

### Провести общую проверку

1. Откройте **«Мастер»** и листы нужных персонажей в соседних вкладках того же браузера.
2. Выберите тип запроса на пульте мастера.
3. На листах появится предложение бросить кубик. Выполните броски; результаты появятся у мастера.
4. При необходимости мастер может бросить за персонажа из его карточки.

### Провести бой

1. Откройте **«Бой»**, добавьте персонажей и противников.
2. Задайте или бросьте инициативу. Для запроса бросков у игроков откройте их листы в других вкладках.
3. Начните бой, отслеживайте текущего участника и переключайте ходы.
4. Изменяйте здоровье, выполняйте атаки и завершите бой по окончании встречи.

## Хранение данных и ограничения

| Данные | Хранилище |
| --- | --- |
| Персонажи, инвентарь, биография, ресурсы | IndexedDB, база `parma`, таблица `characters` через Dexie |
| Активная групповая проверка | localStorage, ключ `parma_session` |
| Состав и состояние боя | localStorage, ключ `parma_combat` |
| Уведомления между вкладками | BroadcastChannel и события `storage` |

- **Сетевого мультиплеера нет.** Разные компьютеры, телефоны, профили браузера и домены не делятся персонажами и боями. Доступ к одному адресу по сети не меняет это ограничение.
- `localhost` и `127.0.0.1`, разные порты, HTTP и HTTPS имеют отдельные хранилища. При смене адреса персонажи могут казаться пропавшими — откройте исходный адрес.
- Очистка данных сайта, удаление профиля или завершение приватного сеанса может удалить персонажей. Экспорт, импорт и автоматическое резервное копирование пока не реализованы.
- Синхронизация рассчитана на локальную игровую сессию; одновременное редактирование одного героя в нескольких вкладках может перезаписать изменения.
- Данные остаются после обычной перезагрузки страницы, но офлайн-загрузка приложения не гарантируется: service worker и PWA-кэш отсутствуют.
- Игровые правила и справочники записаны в коде. Если правило в вашей редакции книги отличается, его нужно сверить и изменить соответствующий модуль.

## Технологии

- **Svelte 5** — компоненты и реактивное состояние через runes.
- **SvelteKit 2** — файловая маршрутизация и сборка приложения.
- **TypeScript 6** — типизация модели и игровой логики.
- **Vite 8** — сервер разработки и production-сборка.
- **Tailwind CSS 4** — утилитарные стили; общий визуальный слой находится в `src/app.css`.
- **Dexie 4** — работа с IndexedDB.

В корневом `+layout.ts` отключены SSR и prerender: экраны используют API браузера. Общая оболочка задаёт навигацию, метаданные и подвал. Лесная иллюстрация и иконки — локальные SVG, внешние шрифты и сервисы изображений не подключены.

## Структура проекта

```text
src/
├── app.html                   # HTML-шаблон, русский язык документа
├── app.css                    # Палитра, общие стили, адаптивность
├── lib/
│   ├── type.ts                # Character, InventoryItem, Money
│   ├── components/            # Общие иконки и доступный Dialog
│   ├── assets/                # Иконка сайта
│   ├── db/characters.ts       # CRUD, миграция полей, начальное снаряжение
│   ├── engine/                # Вычисления и игровые механики
│   │   ├── character.ts       # Характеристики, навыки, ресурсы и умения
│   │   ├── dice.ts            # Броски и классификация результатов
│   │   ├── combat.ts          # Броня, атаки и урон
│   │   ├── conditions.ts      # Эффекты состояний
│   │   ├── inventory.ts       # Предметы, вес и деньги
│   │   ├── spells.ts          # Доступность, стоимость и эффекты магии
│   │   ├── levelup.ts         # Повышение уровня
│   │   └── bestiary.ts        # Масштабирование противников
│   ├── rules/                 # Расы, навыки, предметы, магия и другие справочники
│   └── sync/                  # Локальная синхронизация запросов и боя
└── routes/                    # Страницы приложения
static/forest.svg              # Иллюстрация главной страницы
tests/combat.test.mjs           # Регрессионные тесты удаления участников боя
```

Поток данных: **страница → игровая логика `engine` + справочники `rules` → сохранение `db`**. Модули `sync` отдельно передают изменения боя и общих проверок другим вкладкам.

### Маршруты

| Адрес | Экран |
| --- | --- |
| `/` | Персонажи и быстрый доступ к инструментам мастера |
| `/new` | Создание персонажа |
| `/char/[id]` | Лист персонажа |
| `/char/[id]/levelup` | Повышение уровня |
| `/gm` | Пульт мастера |
| `/gm/combat` | Боевой трекер |
| `/gm/bestiary` | Генератор противников |
| `/gm/cheatsheet` | Шпаргалка |

## Разработка и проверка

```bash
npm run check        # Проверка TypeScript, Svelte и предупреждений доступности
npm run check:watch  # Проверка при изменении файлов
npm test             # Регрессионные тесты боевого состояния
npm run build        # Production-сборка
npm run preview      # Локальный просмотр сборки
```

Тесты используют встроенный `node:test` и выполняют TypeScript через поддержку Node.js 24. Они проверяют сохранение текущего хода при удалении другого участника, передачу хода и переход раунда, пустой бой и удаление неизвестного идентификатора. Это точечные тесты; полного покрытия игровых механик пока нет.

При изменении интерфейса дополнительно проверьте вручную создание и повторное открытие героя, поиск, отмену удаления, переходы по листу, работу диалогов с клавиатуры, синхронизацию двух вкладок и узкий экран. Проверяйте, что изменение цвета не стало единственным способом передать состояние.

Чтобы добавить игровое содержимое, начните с соответствующего справочника в `src/lib/rules`. Меняя расчёты, изменяйте `src/lib/engine`. При изменении модели учитывайте существующие записи IndexedDB и функцию `migrateCharacter` в `db/characters.ts`; изменение индексов или структуры базы требует новой версии схемы Dexie.

## Сборка и размещение

В `svelte.config.js` настроен `@sveltejs/adapter-auto`. Он выбирает адаптер для поддерживаемой среды; для другой платформы потребуется подходящий адаптер и её конфигурация. Установленный `adapter-vercel` напрямую в конфигурации не используется. `npm run preview` предназначен для локальной проверки, а не для постоянного production-хостинга.

Используйте HTTPS при публикации: некоторые браузерные API, включая буфер обмена и генерацию UUID, требуют защищённого контекста (localhost допустим для разработки). При смене домена локальные персонажи автоматически на новый адрес не переедут.
